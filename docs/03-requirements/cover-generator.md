## 需求背景

当前封面生成器将配置表单、素材选择和预览放在同一层级。背景色以 14 组颜色、每组 6 个色阶完整展开，纹理和人物素材也直接占用大量纵向空间，导致用户需要频繁滚动才能完成一次配置。

顶部导出工具栏也同时展示 JPG 和 PNG，但当前业务只需要 JPG。页面整体层级较弱，配置区和预览区的职责不够清晰。

## 目标用户

- 教研老师、制作老师和内容运营人员。
- 使用前提：用户已进入封面图生成工具，需要快速生成项目封面或项目组封面。

## 业务目标

- 将生成封面的最低操作成本降为“输入标题 → 随机生成”，不要求用户先理解全部素材配置。
- 为有明确视觉需求的用户提供直接自定义入口，只开放角色、颜色和纹理三类素材配置，不要求先切换模式。
- 让用户在固定的工作区内完成配置和预览，减少页面跳动与无效滚动。
- 让背景、纹理、角色等资源选择通过浮层按需呼出，未来增加素材时不改变主要布局。
- 统一导出格式为 JPG，降低无效选项和认知成本。
- 保留现有封面绘制、布局匹配、字体加载和下载能力。

## 用户故事

作为内容制作人员，我希望只输入标题就能随机获得一张符合规范的封面；需要精细控制时，也能直接选择角色、背景和纹理，并始终看到真实比例的实时预览。

## 主流程

1. 用户进入 `/cover-generator`。
2. 页面加载封面字体，并展示默认的项目组封面配置和实时预览。
3. 用户在右侧工作台上方选择封面类型，并在左侧输入标题。
4. 用户点击“随机生成”后，系统只从当前封面类型适用的既有角色、背景、纹理和字体规则中随机组合；项目组中文标题同时随机选择图文方向，并更新预览。
5. 用户也可直接点击角色、颜色或纹理入口自定义；标题、布局方向和存储标签继续按既有规则生效。
6. 中部预览区按真实画布比例等比展示并实时重绘封面；预览内部使用 2 倍像素密度，显示尺寸不变。
7. 用户选择 1x 或 2x，点击“导出 JPG”。
8. 系统以 JPG 格式下载封面文件。

## 异常流程

- 字体加载中：下载按钮禁用，配置仍可继续编辑；字体加载完成后恢复下载。
- 标题超出限制：显示超出提示和错误边框，预览仍可展示，下载不额外阻断当前行为。
- 随机结果不可用：若随机到的任一素材加载失败，系统不提交该组合并尝试其他既有素材；没有可用组合时提示失败并保留上一张有效封面。
- 纹理或角色图片加载失败：对应缩略图显示失败占位，不阻断颜色、标题和其他资源操作。
- 未选择纹理：预览不绘制纹理图层，下载仍可执行；适用角色布局始终使用已选角色素材。
- 重复点击下载：下载处理中按钮禁用，避免重复触发。
- 切换封面类型：保留背景、纹理、布局方向和存储标签，为新类型选择有效角色；从项目组切换到项目时将标题截取为前两个字符，切换后不恢复被截取的原标题；标题不符合新类型规则时就地提示。

## 数据埋点方案（待确认）

### 统计口径

- **每日活跃人数**：当天触发过一次 `cover_generator_engaged` 的去重用户数；登录用户按稳定 `user_id` 去重，匿名用户按分析平台生成的 `distinct_id` 去重。
- **使用人次/会话数**：每个连续使用会话只记一次 `cover_generator_engaged`。进入页面但没有标题输入、资源选择、随机生成或导出等有效操作，不计为一次“使用”。
- **导出次数**：每次成功生成并下载 JPG 记一次 `cover_generator_export_succeeded`；点击但因字体、素材或导出异常失败，不计入成功导出。
- **操作路径**：同一个 `cover_session_id` 下，按事件时间戳还原页面进入 → 配置操作 → 随机生成/自定义 → 导出的顺序。

### 事件清单

| 事件 | 触发时机 | 关键属性 |
| --- | --- | --- |
| `cover_generator_opened` | 进入 `/cover-generator` | `cover_session_id`、来源页面、应用版本 |
| `cover_generator_engaged` | 当前会话首次发生有效操作 | `entry_action`、`cover_session_id` |
| `cover_generator_action` | 用户完成一个关键业务操作 | `action_type`、`action_value`、封面类型；标题编辑仅在提交/失焦或防抖后记录 |
| `cover_generator_export_clicked` | 点击“导出 JPG” | 清晰度、封面类型、标题是否有效、当前资源状态 |
| `cover_generator_export_succeeded` | JPG 下载成功 | 清晰度、封面类型、耗时、`cover_session_id` |
| `cover_generator_export_failed` | 导出失败 | 错误码、失败阶段、清晰度、耗时；不得上传原始异常堆栈中的敏感信息 |
| `cover_generator_error` | 字体或素材加载失败、随机生成失败等可观测错误 | 错误类型、资源类型、可重试状态 |

`cover_generator_action.action_type` 只允许使用已登记枚举，例如：`cover_type_changed`、`title_edited`、`layout_changed`、`storage_tag_toggled`、`color_selected`、`texture_selected`、`role_category_selected`、`role_selected`、`scale_selected`、`panel_opened`、`random_generated`。不建议把所有 DOM 点击或每个字符输入都作为事件上传。

### 身份、隐私和失败策略

- 登录后调用分析平台的身份绑定能力，将登录前匿名事件与稳定内部 `user_id` 关联；退出登录时清理身份，避免下一位使用同一设备的人继承前一位身份。
- 当前页面没有登录与后端用户数据能力，因此第一阶段最多得到匿名设备/浏览器维度的使用趋势；要回答“具体哪位老师用了几次”，必须先提供可用的用户身份来源。
- 埋点上报失败不得阻塞标题编辑、预览、随机生成或导出；开发环境默认不写入正式项目数据，并需要区分测试项目和生产项目。
- 是否启用会话回放、采集 IP/地域、保存周期、数据存储区域和数据访问角色，需要单独确认；第一版默认不开启会话回放。

### 推荐查看方式

优先接入产品分析平台（推荐 PostHog，或复用组织已有的同类平台），由平台负责事件接收、用户/会话关联和可视化分析：

1. **趋势报表**：按天查看活跃人数、使用会话数、成功导出数，并按封面类型、清晰度、角色或颜色等事件属性拆分。
2. **漏斗报表**：`opened → engaged → export_clicked → export_succeeded`，查看每一步人数、转化率和流失位置。
3. **路径报表**：以 `cover_generator_opened` 或 `cover_generator_engaged` 为起点，查看用户最常见的后续操作顺序。
4. **单用户/单会话明细**：仅在完成身份绑定后，查看某个用户的事件时间线；匿名用户只能看到匿名 ID，不能当作真实姓名。
5. **自定义查询和导出**：需要逐日逐人统计、与业务表关联或长期 BI 看板时，再使用平台 SQL/API 或导出到组织数据仓库。
